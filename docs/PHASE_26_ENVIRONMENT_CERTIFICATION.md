## Supabase checks

The supplied project URL was reachable. `auth/v1/settings` returned HTTP 200. The anonymous REST root returned HTTP 401, the service-role query for `user_profiles` returned HTTP 404, and `functions/v1/secure-sync` returned HTTP 404 with `NOT_FOUND`. No migration was applied and no user or tenant data was created because the supplied key pair does not provide SQL/Management API access and the project could not be confirmed as disposable staging.

These results indicate that the target project either does not contain the expected schema/function deployment or the requested migrations/functions have not been applied there. A service-role JWT can access deployed PostgREST resources; it is not a Supabase Management API token and cannot create a new project or execute arbitrary migration files.

## Fixes made during validation

No application architecture or commercial feature was changed. Two validation-only test fixes were made: the obsolete test for deleted legacy `ScheduleGenerator` classes was removed, and `DomainUseCasesTest` now correctly accepts suspend lambdas. Android SDK/JDK setup files remain outside the repository. The staging build type from Phase 2.5 was retained.

## Required external steps

To complete Supabase certification, provide a confirmed disposable staging project with Management API/CLI access or enable the Supabase project-management integration. Apply the migrations in the requested order, deploy `secure-sync`, seed two tenants and six users, then run `supabase/tests/phase2_rls_matrix.sql`, `supabase/tests/phase25_sync_matrix.sql`, and the smoke harness. Do not apply them to production.

To complete Android certification, run on a host with hardware virtualization and `/dev/kvm`, or connect a physical Android device with USB debugging. The minimum commands are:

```bash
source /home/ubuntu/android-env.sh
cd /home/ubuntu/borg-pharmacy-pro-audit
./gradlew testStagingUnitTest
./gradlew connectedAndroidTest
./gradlew assembleStaging
adb devices
```

The application-level login, session restore, logout, token refresh, offline queue, reconnect, conflict, and Room upgrade scenarios cannot be honestly marked passed without a booted emulator or physical device and a deployed staging backend.
